# You are one of several Claude sessions in this folder

Deck started this session. The person often runs several Claude tabs in the same project at once, all sharing one working tree, one git index and one branch. Other sessions may be editing, committing, pushing or deploying at the same moment you are. Treat any change you didn't make as someone else's work in progress.

- **Commit only your own changes, by path.** Use `git add <the files you changed>`, never `git add -A`, `git add .` or `git commit -a`. If a file you touched also has another session's edits in it, stage only your hunks (for example with `git apply --cached` on a patch of your own changes). Committing half of someone else's change is how main ends up calling a function that was never committed.
- **Leave other changes alone.** Don't revert, reformat, stash, `checkout --` or `reset` files you didn't change, and don't commit them yourself unless they've clearly sat untouched for a while and build cleanly. A file modified in the last few minutes belongs to a live session.
- **Check before you push.** Run the project's type check or build (for example `npx tsc --noEmit`) and only push if it's clean. If it fails because of someone else's uncommitted work, say so instead of committing their files to fix it.
- **Integrate safely.** If the push is rejected, `git pull --rebase --autostash` and push again (the folder is never clean, so a plain `--rebase` refuses). Keep that the only stash: never a standalone `git stash`, which takes other sessions' edits out from under them for as long as it's held, and if the autostash fails to reapply, stop and say so rather than resolving their files. If git reports `index.lock` exists, another session is mid-command: wait a few seconds and retry, and don't delete the lock.
- **Deploy what was pushed, not the shared folder.** A deploy that uploads the working directory (like `vercel deploy`) also ships other sessions' half-written files. Deploy from a clean checkout in the temp folder (never beside the repo: every folder in `~/projects` shows up in Deck as a project): `git worktree add --detach "$TEMP/<repo>-deploy-<random>" origin/<branch>`, copy in any local deploy config the repo needs (like `.vercel`), deploy from there, then `git worktree remove` it. If another session started a production deploy in the last minute or two, check whether it already includes your commit before starting another.
- **Shared dev servers and ports:** before starting a dev server, check whether one is already running and reuse it rather than killing it.
